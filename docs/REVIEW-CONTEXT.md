# Counterfactual Worlds — independent review brief

**Please critically review this product and implementation.** Identify the three changes that most improve learning and immersion before a hackathon submission. Give concrete UI changes, learning risks, engineering defects, and acceptance checks. Separate observed behavior from inference. Do not assume planned features exist.

**Context.** Solo builder at an OpenAI GPT-6 Astra hackathon. Judging is equally weighted: Astra in development, Astra in the product, live demo, and technical implementation. The deliverable includes a **60-second video showing both teacher and student interfaces**. No claim of learning gains or guaranteed judging results is justified.

**Product.** A teacher creates a source-grounded investigation; students enter an explorable setting, inspect evidence, defend a claim, receive a teacher-directed challenge, and revise. Target subjects are history and English literature. The working app currently has one Alexandria-inspired history lesson. **The Odyssey and Pride and Prejudice are planned, not implemented.** Literature must assess textual interpretation, narration, language, and alternatives—not reuse a historical causal rubric unchanged.

**User priorities.** The student experience must feel immersive rather than like a dashboard. Students should move freely. Models should have architectural detail. Images, source text, and citations must be accessible inside the app. Evidence and revision must drive learning; collecting objects and watching scenery are insufficient. The teacher can retain an operational dashboard.

**Readiness bar.** A memorable live teacher intervention should help a real student revise an evidence-based explanation. The user requires an independent review after integration, not just a prepared video. `docs/PRODUCT-READINESS.md` separates recording, supervised classroom pilot, and broader release gates. The current diagnostic review does not establish final readiness.

**Implemented.** Three.js district with original Blender library/lighthouse GLBs; outdoor walking, touch controls, collision boundaries, and quick travel. Teacher authoring, invitations, persistent classroom/student state, Astra feedback, native mid-turn steering, intervention preview/application. Student view now fills the viewport; field journal and conversation open on demand. An in-app reader shows evidence text, a short verified Strabo excerpt, paraphrase/provenance labels, a citation action, and an original setting illustration explicitly labeled **not primary evidence**. Source buttons in the argument panel reopen the reader. This is not a general document/image ingestion system.

**Learning contract.** Intended loop: question/prediction → examine a source → explain its relevance → cite it → receive a targeted challenge → revise and explain what changed. Current history rubric: claim, evidence, mechanism, limitation. Code checks actual student excerpts and available evidence IDs before awarding points. A score/door unlock is a game milestone, not proof of mastery. Student claim/reply histories persist, but a formal prediction stage, passage selections/annotations, source-version selectors, and explicit before/after reflection are still missing. Current evaluation passes all collected source IDs to the model rather than requiring structured per-claim selected citations.

**Astra's role.** Server-side Responses calls generate bounded world data, assess arguments, and create teaching hints. WebSocket steering lets a teacher correct an in-progress hint. The renderer uses authored templates; arbitrary model-generated code never executes. Primary material, interpretation, assumptions, invented props, and simulated dialogue must stay distinct. Architecture, ship counts, and trade/funding links do not establish ancient historical facts. Sources cannot prove the exact reconstructed building or a counterfactual future.

**Engineering and known gaps.** TypeScript/React on Vinext, Cloudflare Worker + D1, Zod contracts. Twenty deterministic tests and prior live Astra smoke checks passed before this UI pass. Outstanding P0s in the parallel plan include selected-learner director context (currently defaults to teacher preview), atomic authoring/progression races, preserving all reviewed source cards, and broader rubric evaluation. Interventions are classroom-wide. Walking covers exteriors; books need distinct packs, assets, reading/spoiler boundaries, and rubrics. Browser review of the new reader and narrow student layout is limited, not a full accessibility/performance audit. No educational efficacy study exists.

**Review materials.** Repo: https://github.com/henryhehehe/GPT6-hack. Private app: https://counterfactual-worlds-henry.handeche49.chatgpt.site (owner sign-in may prevent reviewer access). Read `components/worlds/Classroom.tsx`, `EvidenceReader.tsx`, `WorldScene.tsx`, `lib/world.ts`, API routes, and `docs/BUILD-LOG.md`. Plans: `docs/PARALLEL-IMPLEMENTATION-PLAN.md`, `docs/LITERATURE-EXPANSION.md`. Five-product research: `docs/LEARNING-UX-RESEARCH.md` (official-source desk review, not account testing).

**Requested review output.** Give a candid readiness verdict; five ranked findings with evidence; a proposed student screen and source-to-revision flow; three falsifiable acceptance checks; and the strongest truthful 60-second teacher/student demonstration. Specify what to cut. Prioritize students' reasoning over extra spectacle. Do not request API keys or include credentials in the review.


### Latest addition: teacher source intake
Teacher studio now accepts pasted text, PDF/TXT/Markdown upload, or direct public PDF link. It automatically extracts/selects material and generates a complete three-station lesson with characters, source cards, activities, what-if, and assessment. Explicit source review precedes idempotent fresh-class launch. D1 stores durable drafts, R2 stores private uploads, and source authorization includes the launched teacher. Literature gets close-reading assessment language. Generated coast/garden/archive settings are symbolic; reviewed native Odyssey/Austen worlds and arbitrary high-fidelity generation remain future work. Canonical source IDs are enforced in the output schema; server code supplies exact saved excerpts and citations. PDF extraction is model-derived and must be checked by the teacher. Inputs are capped at 5 MB PDF / 60,000 text characters. Focus review on extraction/range fidelity, scene usability, and the preserved evidence-to-argument learning loop.
