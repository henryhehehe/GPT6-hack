# Follow-up review: three actionable findings

Reviewed frozen candidate `73a951be1f8a38fc8ca8fbd5206d8fc93bb38c15` (runtime `66ccee2`). Confirmed that all three relevant code paths remain present in the newer public-update source `c0c93fc`. This is a source and offline API review by an implementation agent, not an independent classroom observation. No browser playtest, real model requests, or production data changes were made.

1. **P1 — Shared hint state exposes private teacher context.** `app/api/classroom/route.ts:25` returns the full stored classroom state to students. After a teacher applies a hint based on B, A receives `hint.basis.name`, student ID/revision, and `hint.request`, the original teacher instruction. That instruction may contain individual learner feedback intended only to guide generation. The same full hint enters subsequent dialogue/assessment prompts, bypassing the new name-free director projection. Reproduced against the built Worker with two synthetic learners and an explicitly private teacher note. Return a bounded public hint to learners and downstream model requests; retain basis/request in teacher-only state and responses.

2. **P1 — Reopening a conversation can lose newer unsent writing.** `lib/dialogueDraftStore.ts:43–47` completes an earlier request using its in-memory snapshot, checking only the stored source identity. The dialog can close during sending (`components/worlds/CharacterDialogue.tsx:25–26`). Reopening the same character creates another store with the same key/source. If the learner types a new question before the old reply arrives, the old store writes an empty draft over it. The newer text remains visible until reload, when it disappears. Reproduced with two store instances: visible new question, then empty recovered message. Compare the current stored record/revision and pending request before clearing; test close/reopen and same-key concurrent instances as well as newer typing within one instance.

3. **P2 — Navigating during assessment discards completed feedback.** `components/worlds/Classroom.tsx:128` writes a visit without checking for an in-flight assessment. The visit increments the same student revision used by argument persistence (`app/api/classroom/route.ts:82,103`; `lib/classroomWrites.ts:4`). A successful assessment arriving afterward fails its revision guard and consumes allowance without saving a turn. Reproduced against the built Worker by holding a fixed assessment response, posting a visit, then releasing the response: the server returns a progress-conflict error and the new turn is absent. Keep local navigation available while deferring its metadata write, or reconcile location-only updates without weakening source/progress conflict protection. Cover conversations too, which share this write boundary.

The defects were sent to the active release owner before publication. Fixes and rechecks were still pending when this report was written. The existing 176-test result and earlier release harness did not exercise these interleavings or inspect private fields in student hint payloads.

Reproduction source: `scripts/reproduce-review-findings.mjs`. Run with `node --import tsx` from the candidate checkout while pointing to this script's absolute path. The script reads that checkout's built Worker and migrations, uses disposable local storage and fake credentials, intercepts all outbound requests with fixed responses, and disposes the Worker. It asserts the defective behavior to reproduce these findings; it is not a passing release gate and its assertions should be inverted when implementing regression tests for the fixes.
